\section{Setup}

All arms are trained with PPO for 200 updates ($16$ environments $\times$ $128$ steps per update, $409{,}600$ environment steps) with symlog value targets, and evaluated every 25 updates on 10 held-out episodes with the mean-chain decoding of the belief. The reported number is the evaluation return at update 200 unless marked otherwise. Five seeds (10--14) are run for every arm.

\paragraph{Score-based belief models.}
The belief is a set of $K=16$ particles moved by $L=4$ unadjusted Langevin steps on a learned energy. Three encoders read the particle set: a one-layer Transformer (\emph{score-transformer}, 75{,}286 parameters), an $\alpha$-vector head with 16 pieces (\emph{score-alpha}, 35{,}525 parameters; the \emph{matched} variant widens the trunk to 75{,}269 parameters via a feed-forward width of 704), and a DeepSets encoder (\emph{score-deepsets}, 67{,}222 parameters). Four designs are compared:
\begin{itemize}
  \item \textbf{v1 (cold)}: particles are re-initialised from $\mathcal{N}(0, I)$ at every step; no auxiliary loss.
  \item \textbf{v2 (warm$+$anchor$+$aux)}: particles are warm-started from the previous step and anchored to the observation; auxiliary reward- and next-observation-prediction losses (coefficient 1).
  \item \textbf{v3 (cold$+$aux)}: cold start with the auxiliary losses.
  \item \textbf{v4 (warm$+$anchor)}: warm start and observation anchor without auxiliary losses.
\end{itemize}

\paragraph{Baselines.}
A GRU recurrent policy (75{,}674 parameters), a plain RNN policy (75{,}970 parameters), and a particle-filter policy following PF-RNN/DPFRL with soft resampling and parameter count matched to the score models (76{,}080 parameters). Mountain Hike additionally lists the earlier deterministic particle filter (legacy) for seeds 10--12.

\paragraph{Tasks.}
\emph{Mountain Hike}: 2-D continuous control with horizon 75 and observation noise $\sigma=3$. Scripted reference policies give $-360$ (stationary), $-189$ (observation only) and $-122$ (oracle with the true state). \emph{Light-Dark 2D}: horizon 30, light at $x=5$, initial state $\mathcal{N}(2, 1)$, goal bonus 0, terminal cost 10, and observation noise that grows with the distance from the light (noise gain 5). No scripted reference values have been computed for this task yet; earlier single-seed runs of the same task gave $-25$ (score-transformer) and $-29$ (GRU).

\section{Reading the tables}

\begin{itemize}
  \item \textbf{Mountain Hike.} No score-based design reaches the recurrent or particle-filter baselines ($-146$ to $-188$ on average) or the observation-only reference ($-189$). Warm-started designs (v2, v4) avoid the $-440$ trap more often than cold ones, and score-alpha is the most stable encoder ($-258$ to $-281$ across designs, standard deviation below 55). The auxiliary losses do not prevent the trap (v3). The single strong v2 transformer seed ($-129$) does not reproduce on the other four seeds.
  \item \textbf{Light-Dark 2D.} score-deepsets in v1 and v2 ($-60$ and $-61$ on average) matches the baselines ($-59$ to $-68$). score-transformer is competitive except for one collapsed seed per design. score-alpha is worse on average and its evaluation swings between $-25$ and $-1500$ from one evaluation to the next, so the update-200 value is largely a sampling artefact; Table~\ref{tab:ld2d-tail4} averages the last four evaluations to damp this.
  \item \textbf{Parameter-matched score-alpha.} Widening the $\alpha$ trunk to the transformer's parameter count does not help: on Mountain Hike it pushes v1 and v3 into the trap on most seeds, and on Light-Dark 2D it makes the evaluations even more volatile. These runs are still in progress; asterisks mark the latest available evaluation.
  \item \textbf{Failure.} Light-Dark 2D particle filter seed 10 stops at update 46 with a non-finite gradient norm; a resume reproduces the failure because the stored rollout is replayed deterministically.
\end{itemize}
